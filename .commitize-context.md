SeqFu: a Nim suite of command-line tools for FASTA and FASTQ manipulation.
Most tools are subcommands of one binary (`seqfu <command>`), plus some
standalone `fu-*` binaries. Users are bioinformaticians: describe changes by
what the command does to their reads and files.

## Scope = the command name

The scope is the command as users type it, never the source file name.
Look up the changed file here (source file -> scope):

- fastx_stats_v2 -> stats; fastx_count_threads_v3 -> count;
  fastx_count -> count-legacy
- fastx_grep2 -> grep; filter_byid -> by-id; filter_bycomment -> by-comment;
  filter_byseq -> by-seq
- fastq_interleave -> interleave; fastq_deinterleave -> deinterleave
- fastq_merge -> merge; fastq_merge_lanes -> lanes
- fastx_derep -> derep; fastx_sort -> sort; fastx_rc -> rc
- fastx_view -> view; fastx_view_interactive -> less
- fastx_tabulate -> tabulate; fastx_check -> check; fu_rotate -> rotate
- shred, fu_shred -> shred; msa, fu_msa, lib/msa_reader -> msa;
  fu_orf -> orf; fu_tabcheck -> tabcheck
- Other fastx_*/fastq_* files: drop the prefix (fastx_trim -> trim,
  fastx_cat -> cat, fastx_bases -> bases, fastq_amplicheck -> amplicheck,
  fastx_homocomp -> homocomp, fastx_subtract -> subtract, tofasta -> tofasta)
- Standalone tools: the binary name (fu_cov -> fu-cov, fu_index -> fu-index,
  fu_sw -> fu-sw, fu_virfilter -> fu-virfilter, fu_nanotags -> fu-nanotags,
  fu_primers -> fu-primers, fu_multirelabel -> fu-multirelabel,
  dadaist2_region -> fu-16Sregion, dadaist2_mergeseqs -> dadaist2-mergeseqs)

Files outside src/ still get the command scope:
- test/test-<name>.sh -> <name>, except test-tab -> tabulate,
  test-byid/bycomment/byseq -> by-id/by-comment/by-seq, test-orflegacy -> orf,
  test-index/primers/virfilter -> fu-index/fu-primers/fu-virfilter,
  test-dadaist2-region -> fu-16Sregion
- docs/tools/<name>.md -> <name>

Only when no single command is involved:
- src/sfu.nim (dispatch, aliases, global help) -> `seqfu`
- shared code (seqfu_utils, seqfu_records, seqfu_legacy_fastx,
  stats_utils, merge_utils, filter_utils, lib/) -> `utils`
- seqfu.nimble dependencies -> `deps`; Makefile, *.cfg, nimble targets,
  Dockerfile, seqfu-latest.def -> `build`; .github/workflows -> `ci`
- other docs/ pages -> `docs`; README.md, AGENTS.md, CITATION.cff -> `readme`;
  CHANGELOG and version bumps -> `release`

If a shared file changes only to support one command, use that command.
If several commands change equally, leave the scope out. Never use old
scopes like fastx_trim, tools, source or entrypoint.

## Types

- `feat`: new command, option, output field or format.
- `fix`: wrong counts, sequences or qualities, crashes, bad handling of
  empty files, gzip, missing qualities or paired-end mismatches.
- `perf`: same output, faster or lower memory (threads, streaming).
- `refactor`: same behaviour, restructured code.
- Only test/ changed -> `test(<command>)`. Tests shipped with a feature or
  fix take the feature or fix type.
- Docs, README, AGENTS.md, images and this file are `docs`, never `feat`.
- Build and container changes are `build`, not `chore`.

## Wording

- Write flags with dashes: "add --gz-level option".
- Say FASTA/FASTQ in capitals and "paired-end" with a hyphen.
- Call out output-format changes (columns, JSON keys, headers):
  they break downstream pipelines.
- Ignore bin/ build outputs.
- Keep the subject under 72 characters; put details in body bullets.
