seqfu: a Nim package for FASTA and FASTQ manipulation offering a broad set of utilities 
accessed as 'seqfu command args'; 

## Scopes

Pick the scope from the files that carry the main change. Use lowercase only.

- docs: docs/ (jekyll website with the documentation, rendered with GitHub pages)
- entrypoint: src/sfu.nim is the main source file
- source: src/*nim is either a utility or a subcommand
- extra: src/*.c, src/*.cpp are helper tools
- scripts: scripts/* are scripts that are now deprecated 
- package: seqfu.nimble and Makefile
- release: changelog generation, wherever the code lives
- readme: README.md, the logo and other images
- deps: seqfu.nimble
- ci: .github/workflows

For a change that spans several modules, use the scope of the user-facing
part (usually cli), or leave the scope out.

## Types

- README, AGENTS.md, CLAUDE.md, images and this file are always `docs`,
  never `feat`. Some older commits say `feat(readme)` or `feat(docs)`;
  do not copy them.
- A change to prompt wording that changes the generated messages is
  `feat(prompt)` or `fix(prompt)`, not `refactor` or `chore`.
- A change that only touches tests/ is `test`, with the scope of the
  module under test, e.g. `test(git): cover untracked files in diff`.
- Dependency bumps and uv.lock updates are `chore(deps)`. Packaging or
  build-backend changes in pyproject.toml are `build`.
- Workflow changes are `ci`.

## Wording

- Write CLI flags as typed, with their dashes: "add --summary flag",
  not "add summary option".
- Name config keys in full, e.g. `commit.max_diff_bytes`.
- Say "LLM" for the model, and name a provider only when the change is
  specific to it (e.g. OpenRouter headers or cost reporting).
- If a new commit option is added to both the root callback and `commit`,
  that is one change: do not add a bullet for the second copy.
